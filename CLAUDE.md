# Betts Board — contributor conventions

Self-hosted family organizer. Nuxt 4 full-stack (Nitro node-server preset), SQLite via
Drizzle, Nuxt UI v4 (bundles Tailwind v4), zod v4. One long-running container in prod.

## Architecture: vertical feature slices

Every feature owns a folder at each level and touches nothing outside them:

- `app/components/<feature>/` — Vue components (auto-imported by filename)
- `app/pages/…` — that feature's pages only
- `server/api/<feature>/` — thin Nitro routes: validate → call service → return
- `server/services/<feature>/` — ALL business logic (unit-testable without HTTP)
- `server/db/schema/<feature>.ts` — tables (already complete; do not edit)
- `shared/schemas/<feature>.ts` — zod contracts (already complete; extend only if missing something)

Shared infrastructure (do NOT modify): `nuxt.config.ts`, `package.json`, `server/db/schema/*`,
`drizzle/*` migrations, `server/middleware/auth.ts`, `app/middleware/*`, layouts,
`server/utils/session.ts`, `server/db/client.ts`.

## Server conventions

- DB access: `useDb()` from `server/db/client.ts`; tables from `server/db/schema`.
  better-sqlite3 driver is synchronous: use `.get()` / `.all()` / `.run()`.
- Auth inside routes (the global middleware already blocks locked-out requests):
  - `requireProfile(event)` → `{ session, profile }` — most feature routes
  - `requireUnlocked(event)` — read-only routes that don't need an acting profile
  - `requireAdmin(event)` — destructive/settings routes
  - `requireHousehold()` — the single household row (settings, timezone, location)
- Validation: `await readValidatedBody(event, someSchema.parse)` /
  `await getValidatedQuery(event, someSchema.parse)` with schemas from `#shared/schemas/<feature>`.
- Errors: `throw createError({ statusCode, statusMessage })`.
- IDs are UUIDv7 strings, generated by column defaults — never generate manually.
- Timestamps are `{ mode: 'timestamp_ms' }` → JS `Date` in code, epoch-ms in DB.
- Calendar dates (all-day events, chore due dates, meal-plan dates) are `YYYY-MM-DD`
  strings and must NEVER pass through a timezone conversion. Helpers in `shared/utils/dates.ts`.
- Files on disk: `dataDir()` / `uploadsDir(...)` from `server/utils/dataDir.ts`; serve
  through `/uploads/**` (session-gated route), never expose absolute paths.
- New API routes must be registered in `server/services/apiDocs/registry.ts` — the
  OpenAPI coverage test (`tests/unit/openapi.spec.ts`) fails otherwise.

## Recurrence

`server/services/calendar/recurrence.ts` + `expand.ts` are the ONLY places rrule is
imported. Events store a bare RRULE body (no DTSTART) + authored timezone; chores are
date-only. To expand occurrences, call the calendar service — never rrule directly.

## Frontend conventions

- Nuxt UI v4 components (`UCard`, `UButton`, `UInput`, `UFormField`, `USelect`, `UModal`,
  `USwitch`, `UBadge`, `UTextarea`), `useToast()` for feedback, `i-lucide-*` icons.
- Tailwind utilities; support dark mode (`dark:` variants, slate palette like existing files).
- Mobile-first: bottom nav is 5 tabs + a More bottom sheet (which also holds the profile
  switcher and Lock); check-off targets ≥ 44px. `/tv/*` pages use
  `layout: 'tv'` (rem scaling ×1.75, D-pad focus rings — no hover-only UI).
- App-stage state: `useBoardState()` (bootstrap, activeProfile, isAdmin, switchProfile).
- Data fetching: `useFetch` for SSR-visible page data, `$fetch` for mutations; refresh
  after mutations rather than hand-syncing local state.
- Per-device flags: `useDeviceMode()` (wall-display toggle).
- The dashboard (`app/pages/index.vue`) composes per-feature tile components — implement
  your feature's tile in your component folder; don't restructure the dashboard.
- The settings page composes per-feature section components the same way.

## Testing

- Vitest specs in `tests/unit/*.spec.ts` (plain node env; config in `vitest.config.ts`;
  `#shared` and `~~` aliases available). Test services, not HTTP routes.
- DB-dependent services: build an in-memory db via `createDb(':memory:')` from
  `server/db/client.ts`, run `migrate(db, { migrationsFolder: 'drizzle' })` from
  `drizzle-orm/better-sqlite3/migrator`, then `setDb(db)` so services see it.
- Fixtures (saved recipe HTML, .ics files) live in `tests/fixtures/`.

## Commands

- `npm run dev` / `npm run build`
- `npm test` — vitest run
- `npm run lint` / `npm run typecheck`
- `npm run db:generate` — regenerate migrations after schema changes (foundation only)
